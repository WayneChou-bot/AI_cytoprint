# MorphoProfile — 細胞影像形態分析與作用機制檢索

[English](README.md) · [繁體中文](README.zh-TW.md)

**不需要分子式,看細胞長什麼樣就推測藥物的作用機制(MoA)。**

一條在開源 [Cell Painting](https://doi.org/10.1038/nprot.2016.105) 資料上端到端、可重現的管線:
原始五通道顯微影像 → 細胞核分割 → 形態指紋 → 最近鄰 MoA 檢索,另附一套經嚴謹驗證的批次校正比較。

所有數字都由本 repo 的程式從公開資料**離線計算**,再嵌入單一自足的 `index.html`。**沒有任何虛構或示意數據。**

「候選活性」是啟發式篩選,明確不是顯著性檢定。各章節的個別限制在本文件與網站上都有逐項說明。

## 這是什麼

多數藥物開發 ML 都在拚「分子 → 性質」預測,那是過度 benchmark 的紅海。本專案改用另一種輸入:**影像**。
從細胞影像建立形態指紋,再用**表徵學習 + 檢索**推測機制——這個切入點 solo 開發者少、且能直接發揮電腦視覺技能。

作品分三層,每一層各自證明什麼、不證明什麼,README 都誠實交代。

| 層 | 做什麼 | 規模 | 證據等級 |
|---|---|---|---|
| **1. 影像 → 指紋**(`images/`) | 真實五通道影像 → 自建細胞核分割 → 59 個形態特徵 → 對 DMSO 標準化 | 9 個化合物、701 顆細胞 | **案例展示** — 證明管線可運作、生物學說得通;**非**統計驗證 |
| **2. Profile 分析**(`pipeline.py`) | 已算好的 CellProfiler profiles → 清理 → 共識指紋 → UMAP、MoA 檢索、候選活性篩選 | 19,200 wells、561 化合物、587 特徵 | **主要量化結果** — 可重現、第三方可驗證 |
| **3. 去偏評估**(`mvp/`) | 雙指標 + plate-block bootstrap + 配對 ΔCI | LINCS(50 盤);JUMP-Target(16 盤、4,102 wells) | LINCS:輔助性量化。JUMP:**探索性** — plate 與條件混雜(見下) |

刻意把這件事講清楚:並不是每一區都是正式驗證,而**願意明講哪些是、哪些不是**,才是可信分析與包裝過的 demo 的差別。

第 2 層用 profiles 而非像素,是因為這是本領域的**標準分工**——Broad 研究所已為整個 JUMP 跑完 CellProfiler
並公開結果,下載約 127 TB 原始影像既不必要也不明智。第 1 層的存在,是為了讓作品仍能完整展示影像處理的那一半。

## 重點成果

### 影像管線重現了已知生物學

用**我自己的 59 個特徵**(不是官方 CellProfiler profile),在真實 CPJUMP1 影像上:

| 化合物 | 機制 | 核面積中位數 | vs DMSO | 細胞數 |
|---|---|---|---|---|
| DMSO | 對照 | 934 | — | 95 |
| **AMG900** | Aurora 激酶抑制劑 | **1389** | **+49 %** | 38(40 %) |
| **FK-866** | NAMPT 抑制劑 | **451** | **−52 %** | 36(38 %) |
| quinidine | 離子通道阻斷劑 | 928 | ≈ 0 % | 94(99 %) |

兩個最強表型的核大小變化**方向相反**,且各自符合已知機制(Aurora 抑制 → 胞質分裂失敗 → 多倍體巨核;
NAD⁺ 耗竭 → 凋亡染色質濃縮),而弱表型的對照藥幾乎不動。另一個提示性的觀察:指紋似乎也不純粹是
「死了多少細胞」——dexamethasone 細胞損失很少卻排第 3,其特徵由粒線體訊號下降主導,
與醣皮質素受體作用於粒線體的文獻一致。

> **本層的定位:**這是一個**案例式的端到端展示**,每個化合物只有**一個 field**。
> 它證明的是**管線能運作、且生物學上說得通**——**不是統計驗證,也不宣稱可泛化**。
> 其中的「細胞」是同一個 field 內的觀測值,不是獨立的實驗重複,因此不做也不隱含任何顯著性檢定。

### 561 個化合物的 MoA 檢索

在標準化共識指紋上做最近鄰檢索:
**Top-1 = 9.0 %**、**Top-5 召回 = 14.9 %**,對照**排除自身**的隨機基準 **0.71 %**
(**約 12.7 倍於隨機**,n = 377 個可評估化合物)。

數字不高但明顯優於隨機——而且誠實呈現。這個落差正是「需要更強表徵與經驗證的批次校正」的動機。

### 逐 MoA 拆解:平均數是這裡最沒有資訊量的一個數字

那個 9.0 % 是**依查詢數加權**的平均。同樣這 113 個類別,改成**依類別等權(macro)只有 6.1 %**;
Top-5 則是查詢加權 14.9 % 對 macro **10.6 %**。兩個都對——它們回答的是不同問題
(「隨機抽一個**化合物**會不會被檢索對」對上「隨機抽一個**類別**表現如何」)——只報一個等於選了一個對自己有利的定義。

兩者的差距來自極端的異質性:**113 個類別中有 102 個是 0 % Top-1**,但另有一小群接近滿分,
而且**全部 Top-1 命中有 59 % 只來自 5 個類別**(其中 7 個命中來自 n < 5 的小類別,見下方告誡)。
把分布攤開,比引用它的平均值有用得多:

數值以 `命中數/查詢數` 呈現,而非只給比率,並附**描述性**二項 Wilson 95% 區間——這些類別多半很小,單看百分比會把這件事藏起來。
稱「描述性」是因為同一類別內的查詢共用同一個鄰居池與同一組 embedding,命中並非獨立的 Bernoulli 試驗:
這個區間用來提醒不確定性,**不是**整條檢索管線的推論型信賴區間。

| MoA 類別 | n | Top-1 | Wilson 95% CI | Top-5 | mAP |
|---|---|---|---|---|---|
| Aurora 激酶抑制劑 | 5 | **5/5** | 57–100 % | 5/5 | 0.834 |
| HDAC 抑制劑 | 3 | **3/3** | 44–100 % | 3/3 | 0.783 |
| mTOR 抑制劑 | 9 | **8/9** | 57–98 % | 8/9 | 0.728 |
| 糖皮質素受體促效劑 | 9 | **7/9** | 45–94 % | 8/9 | 0.641 |
| JAK 抑制劑 | 5 | 2/5 | 12–77 % | 2/5 | 0.110 |
| 蛋白酶體抑制劑 | 3 | 1/3 | 6–79 % | **3/3** | 0.583 |
| 拓樸異構酶抑制劑 | 7 | 2/7 | 8–64 % | 3/7 | 0.086 |
| EGFR 抑制劑 | 6 | 1/6 | 3–56 % | 3/6 | 0.080 |
| 環氧合酶抑制劑 | 14 | 1/14 | 1–32 % | 3/14 | 0.050 |
| 血清素／腎上腺素／組織胺／多巴胺受體配體 | 7–13 | **0** | — | 0–29 % | ≤ 0.04 |
| 磷酸二酯酶抑制劑 | 11 | **0/11** | 0–26 % | 1/11 | 0.026 |

這些區間正是網頁上寫「**在本資料集中呈現高檢索成功率的少數 MoA**」而不是「已接近解決」的原因:
即使是完美的 5/5,Wilson 下界也只到 57 %。

這個落差是**機制上可解釋的,不是隨機的**。表現好的那一群——Aurora 激酶、HDAC、mTOR、蛋白酶體
——全都直接干擾細胞週期、染色質、蛋白質降解或生長訊號,因此會改變細胞**看起來的樣子**:
核變大、分裂受阻、細胞骨架重組。形態指紋抓的正是這些。而 0 % 的那群壓倒性地是 GPCR、離子通道
與訊號調節劑。

這些失敗**不能單純歸因於演算法**——但也不能排除方法端的因素:表徵可能不夠好、相似度度量可能不適合、
每化合物 consensus 可能壓掉亞群反應、單一 MoA 類別本身可能含多種表型,MoA 標註品質也會影響。
較精確的說法是:**assay、細胞條件與表徵共同決定了可檢索的上限**。
(上述「機制上一致」只適用於這裡點名的代表性零命中類別,不是說 102 個全部同屬一種機制。)

#### 檢索失敗真的隨表型強度變化嗎?

這個問題應該用量的,不是用宣稱的,所以 pipeline 直接算了:

| | n | 候選活性比例 |
|---|---|---|
| 被正確檢索(Top-1 命中) | 34 | **88.2 %** |
| 未被正確檢索 | 343 | **21.6 %** |

在 n ≥ 5 的 19 個類別上,類別 Top-1 與候選活性比例的 **Spearman ρ = 0.826**(p = 1.4 × 10⁻⁵),
與活性中位數則是 ρ = 0.747(p = 2.4 × 10⁻⁴);全部 113 類一起看是 ρ = 0.408(p = 7.2 × 10⁻⁶)。
這些應視為**探索性**結果:只有 19 個類別,而活性門檻與 n ≥ 5 篩選都是本分析設計的一部分。

**這不能證明什麼**:候選活性是**從同一批形態特徵推導出來的**,所以這是描述性的支持,
**不是獨立的生物驗證**——兩個都由形態決定的量相關,無法證明化合物在生物上是惰性的。
檢索失敗還可能來自:Cell Painting 的五個通道沒捕捉到該效應、劑量或時間點不合適、
反應只發生在少數細胞或呈非線性、以及活性門檻本身只是一個估計規則。因此本 repo 的主張刻意收窄為:

> 多數失敗類別在**本 assay、此劑量與時間點、此表徵與活性判準下,未呈現足以支撐可靠檢索的可偵測形態表型**。

而不是「多數化合物沒有表型」。

**而且活性不是充分條件**:cytochrome P450 抑制劑有 40 % 的化合物通過活性門檻、
磷酸二酯酶抑制劑有 27 %,兩者 Top-1 都是 **0 %**。有表型不代表**該類別內部共享同一種表型**;
檢索要成功,需要「有訊號」**且**「同類的訊號一致」。

但「受體配體都不行」會是錯的結論:**糖皮質素受體促效劑也是受體配體,Top-1 卻有 78 %**,
因為 A549 確實表現 GR,而且其下游是強烈的轉錄重編程。判準不是藥物的標靶類別,
而是**這個細胞株對它有沒有反應**。

**樣本數**:113 個類別中有 57 個只含 2 個化合物,此時 Top-1 只能是 0 % 或 100 %;互動圖因此預設過濾為 n ≥ 5。
那個 59 % 的集中度是對**全部**類別計算的,且包含 7 個來自 n < 5 小類別的命中,
因此**不應該**和 n ≥ 5 的圖表混在一起理解。

**兩個 mAP 是不同的估計量,刻意不可互相比較**:本節的 mAP(macro **0.073**、查詢加權 **0.091**)
是先做每化合物 consensus 再標準化;去偏那節的 mAP(raw ≈ **0.088**)是先標準化 well 再做 consensus。
兩者都合理、各自內部一致,但屬於不同的表徵,**兩個數字不可互相比較**。

`test_consistency.py` 會從已發布的鄰居表重新計算每個類別的比率、核對 `命中數/查詢數` 與比率一致、
確認每個 Wilson 區間都包含其估計值、驗證**兩種平均**,並斷言查詢加權版能重現頁首的 Top-1。

### 批次校正:用量的,不是用猜的

校正在**兩個軸同時**評估(只顧一軸很容易靠犧牲另一軸「贏」),在**共同的 50 維維度**下進行
(三種表徵各自做自己的 PCA,共享的是維度而非同一組座標軸),
並用 **plate-block bootstrap** 與**配對** Δ 信賴區間。

**探索性**的 JUMP-Target 結果(`mvp/jump_mvp_results.json`,16 盤、4,102 個處理孔)。

CPJUMP1 的 **16 個 compound plate 每一盤都只含單一細胞株與單一時間點**(已在 metadata 驗證),
plate 完全巢狀於 `cell_line × timepoint`。因此對 plate 做校正,在數學上無法與「移除 U2OS vs A549、
24h vs 48h 的真實差異」區分;而 *pooled* 的 MoA 檢索正是跨這些條件彙總,偵測不到這個損失。

合併分析(混雜,僅供對照):

| 表徵 | 生物訊號(MoA mAP,95 % CI) | 批次混合(越接近 1 越好) | Δ vs raw(95 % CI) |
|---|---|---|---|
| raw | 0.154 [0.130, 0.201] | 3.08 [2.57, 3.57] | — |
| sphered(ZCA) | 0.180 [0.134, 0.246] | 1.85 [1.52, 2.14] | +0.025 [−0.044, +0.098] |
| sphered + Harmony | 0.131 [0.087, 0.193] | 1.04 [0.85, 1.24] | −0.023 [−0.084, +0.045] |

> **Harmony 改善了 plate 混合,而 pooled 的 MoA 檢索沒有測到損失。但因為在 CPJUMP1 中 plate 與
> cell line、timepoint 混雜,這個結果無法區分「移除技術變異」與「移除條件特異的生物訊號」。**

**條件關聯結構保留度**正是用來量化這件事(同一組 embedding 上的 kNN 同標籤富集度;1.0 代表該條件已無法分辨):

| 表徵 | 細胞株 | 時間點 |
|---|---|---|
| raw | 1.62 | 1.28 |
| sphered(ZCA) | 1.21 | 1.10 |
| sphered + Harmony | 1.11 | **1.02** |

Harmony 近乎完美的批次混合(3.08 → 1.04),伴隨的是時間點的條件結構**幾乎被完全抹平**(1.28 → 1.02),
細胞株結構的超額富集也砍掉一半以上(1.62 → 1.11)。

這裡的解讀必須刻意保守。可以說的是:Harmony **大幅移除了條件關聯結構(condition-associated structure)**;
由於條件與 plate 完全混雜,這份結構**可能包含真實的生物差異**——**本設計無法量化其中生物與技術各佔多少**。
也就是說,批次混合的分數確實是靠移除條件關聯結構換來的,其中的生物成分有受損風險;
但**不能說已經證明刪掉了真生物**。

**分層評估**——在每個 `cell_line × timepoint` 分層內各自評估,此時 plate 才是真正的技術重複
(每層 4 盤、約 1,000 wells、260 化合物、26 個合格 MoA 查詢):

| 分層 | raw mAP | Δ sphered(95 % CI) | Δ sphered+Harmony(95 % CI) | raw 批次混合 |
|---|---|---|---|---|
| A549-24h | 0.159 | **−0.069** [−0.160, +0.028] | **−0.098** [−0.166, +0.028] | 1.45 |
| A549-48h | 0.187 | +0.020 [−0.030, +0.080] | +0.011 [−0.031, +0.056] | 1.10 |
| U2OS-24h | 0.154 | −0.011 [−0.046, +0.042] | −0.012 [−0.079, +0.068] | 1.18 |
| U2OS-48h | 0.166 | +0.014 [−0.032, +0.103] | +0.010 [−0.036, +0.088] | 1.57 |

由此得到兩個結論。其一,**條件內的批次效應其實不大**:raw 批次混合只有 1.10–1.57,而非合併時的 3.08
——合併時的 plate-label 富集主要由**條件之間**的結構主導,而非同一條件內 plate 之間的差異。
這符合 CPJUMP1 是**單一 source、單一 site** pilot 的預期。其二,**在目前這個探索性 bootstrap 下,
八個 Δ 的 95% CI 全部跨過 0**:在這個設計與樣本量下(每層 26 個合格查詢,合計 104 個),
兩種校正方法都測不到生物效益,也測不到明確損害。CI 偏寬,**不足以排除中等幅度的效應**
——「在此測不到」不等於「無效」。

四個分層之間**並不齊一**,這點值得標出來而不是被平均掉。其中三層的 |Δ| 都 ≤ 0.02,
只有 **A549-24h 是 −0.069(sphering)與 −0.098(+Harmony)**——點估計比其他層大好幾倍,
區間也只是勉強碰到 0。以每層 26 個查詢的功效,這既可能是該層真實的損害,也可能只是雜訊,
本資料無法分辨;但它是最值得用更多查詢或更多 field 追下去的訊號。

關於這個 bootstrap,有兩件事值得攤開講,而不是埋起來。第一,所有點估計都是**全資料上的觀測值**;
bootstrap 只用來估計離散程度,區間再以觀測值為中心重新錨定。這很重要:mAP 對「池子裡有哪些化合物」
是非線性的,所以 bootstrap 抽樣的平均值是**有偏的**——在 LINCS 上,舊版檔案把 sphered+Harmony 的 Δ 報成 −0.00,
而觀測差值其實是 **+0.008**(抽樣平均為 +0.001,低估了八倍,早期抽樣次數較少時甚至會反號)。本 repo 早期版本報的正是那個有偏平均;現已改掉,
並在每個 Δ 旁一併寫出 `bootstrap_mean`,讓落差看得見。第二,對 4 個 plate 做 block bootstrap,
本質上只有 **35 種相異的重抽組合**(`C(2k-1, k)`),提高抽樣次數只會細化權重,不會提高解析度。
每份結果 JSON 都會寫入 `n_distinct_block_draws`;光憑這一點,分層的區間就該被當成探索性結果看待。

`mvp/jump_mvp.py` 會自動完成上述三步:偵測並揭露巢狀結構、跑條件訊號保留診斷、再做分層評估,
並在結果 JSON 中寫入 `"status": "exploratory"` 與明確的 `caveat` 欄位。

> **關於科學誠信的說明**:本專案早期版本對批次校正得出的是**相反**結論。追查後發現是資料品質 bug——
> winsorize 只被用來挑選特徵名稱、卻**沒有寫回分析矩陣**,導致約 176 個近零-MAD、數值高達 1e19 的
> 特徵主導了所有距離計算。修正後結論反轉。修正方式、快取失效機制與更正後的數字都保留在 repo 中。

## 方法說明

**特徵清理(`pipeline.py`)**:非有限值 → NaN;max |值| 超過 100 的特徵視為 MAD 爆掉的假象並丟棄;
其餘 winsorize 到 ±15 **並寫回**;之後才做變異數與相關性過濾。下游只讀這份清理過的矩陣,
且 `data/manifest.json` 記錄 commit、清理規則與版本標記,衍生檔名本身也帶版本
——因此不同版本產生的快取「看得出來」,而不是被無聲重用。這是**來源記錄,不是強制的完整性檢查**:
程式並不會在讀取前驗證雜湊值。

**指標**:檢索使用標準化的每化合物共識指紋上的餘弦相似度。隨機基準**排除查詢自身**,
並依合格查詢的類別大小計算:`mean_i (size(MoA_i) − 1) / (P − 1)`。網頁上的鄰居表與頭條指標
由**同一套計算**產生——`test_consistency.py` 會斷言第三方能從其中一個精確重算出另一個。

**候選活性**:啟發式篩選(共識到 DMSO 中心的 L2 距離超過 DMSO-only 虛無分布第 95 百分位),
刻意標示為**候選活性**而非**顯著**——因為沒有 plate-matched null、沒有白化、也沒有 per-compound FDR。
嚴謹版應改用 replicate mAP 搭配 permutation p-value 與 FDR。

**通道對應——已核對確認**:已比對 CellProfiler pipeline 實際使用的權威對照表
`load_data_csv/2020_11_04_CPJUMP1/BR00117010/load_data.csv.gz`,其 `FileName_Orig*` 欄位給出
`ch1 = Mito`、`ch2 = AGP`、`ch3 = RNA`、`ch4 = ER`、`ch5 = DNA`,以及
`ch6/7/8 = HighZBF / LowZBF / Brightfield`,與先前的實證判定**完全一致**。複驗方式:

```bash
git lfs pull --include="load_data_csv/2020_11_04_CPJUMP1/BR00117010/load_data.csv.gz"
```

## 限制

- 影像層**每個化合物只有 1 個 field、無實驗重複**——機制表是對已知化合物的 sanity check,不是統計結果。
  同一 field 內的細胞不是獨立重複;也未證明表型強度獨立於細胞密度或細胞死亡。
- **JUMP-Target 比較為探索性**:CPJUMP1 中 plate 與 `cell_line × timepoint` 完全混雜,
  pooled 結果無法區分技術變異與條件特異的生物訊號,應改看分層輸出。
- **頁首的 Top-1 是對極不對等的類別取平均**——113 個 MoA 類別中有 102 個是 0 %,而 5 個類別就貢獻了
  59 % 的命中。在假設這個方法能用在某個標靶類別之前,請看逐 MoA 拆解,不要看平均值。
- **59 個自建特徵**是 CellProfiler(1,747 特徵)的簡化重製版,目的在展示端到端能力,不是取代它。
- 瀏覽器上傳功能執行的是**簡化分析**(單通道灰階、Otsu、連通元件、三個統計量),不等於 Python 的 59 維指紋。
- LINCS 是**單一中心**資料,批次效應本來就小,其結果不應一般化到多來源的 JUMP。
- 換到完整 JUMP `cpg0016` **不是換個網址就好**:各 subset 前處理不同
  (compound = 特徵選擇 + Harmony;CRISPR = sphering + Harmony + PCA;ORF = sphering + Harmony),
  且對約 11.6 萬個化合物做 all-pairs 餘弦是超過 100 GB 的稠密矩陣——必須改用 FAISS 或分塊 top-k。
- 目前 mAP 為 query 等權,應同時報告 macro-averaged-per-MoA。

## 後續規劃

1. 把啟發式活性篩選換成 replicate mAP + permutation p-value + FDR。
2. 影像層擴充到每化合物多個 field,才有統計可言。
3. 自監督影像 embedding(DINO 類)取代手工特徵——需要 GPU,且影像量要遠多於目前的 9 個 field。
4. 用 FAISS / 分塊 top-k 把檢索擴到完整 JUMP `cpg0016`。
5. 加上 LLM 層,但**只解說已檢索到的證據**,絕不宣稱未經檢索的機制。
